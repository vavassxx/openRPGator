# Тестовый хост `examples/host`

Готовый игровой полигон для проверки движка end-to-end: карта `town.rmap` + луа-скрипты
с NPC, диалогами, триггерами, патрулями и «дирижёром» глобальных событий.

## Состав

| Файл | Сущность | Что показывает |
|------|----------|----------------|
| `town.rmap` | карта 20×20, v2 | бинарный `.rmap`, локальный рендер на клиенте; префабы сущностей = имена спрайтов, у сущностей есть `scale` |
| `portal.lua` | арка у входа (0,1) | `on_enter` + диалог, телепорт игрока через `player.set_position` |
| `portal_exit.lua` | арка выхода (16,4) | тихо-телепорт обратно на спавн |
| `guard.lua` | Стражник (10,7) | `on_interact`, вложенный диалог, имя игрока в реплике |
| `elder.lua` | Старейшина (12,11) | квест с состоянием в скрипте, разные ветки при повторном обращении |
| `merchant.lua` | Торговец (8,12) | «покупка» с однократностью (после продажи товара — отказ) |
| `chest.lua` | Сундук (13,9) | `world.destroy` собственной сущности по `id` |
| `rat.lua` | Крыса (9,14) | автономное движение: `entity.on_tick` + `set_position` каждые 10 тиков; размер из скрипта `set_scale(0.75)` |
| `well.lua` | Колодец (11,13) | «эффект»-интеракт без покупки/квеста; `scale` 1.25 из карты |
| `sky.lua` | невидимый «дирижёр» (19,19) | глобальный `engine.on_tick`, notify по таймеру |
| `lava` (без скрипта) | пылающая руна (15,11) | опасный объект: пока игрок стоит в зоне, **мировой хост снимает 1 HP за тик** |
| `heal` (без скрипта) | светлая руна (6,12) | лечащий объект: пока игрок стоит в зоне, **+1 HP за тик** (кап на максимум) |
| `hud.lua` | невидимый «мировой хост» (19,18) | скриптовое здоровье игроков (хранится в Lua!), зоны рун, и **host-инициированный HUD**: каждый тик каждому игроку шлётся схема `engine.layout` (панель + полоска + число «HP N/100» слева сверху) |
| `healer_npc.lua` | Целитель (6,4) | интерактивный NPC с ветвящимся диалогом: объясняет руны и систему здоровья |

Новые спрайты для рун — `sprite/lava.png` и `sprite/heal.png` (см. пересборку пака ниже).

## Запуск

Эта папка и есть **host-контент сервера**: карта `town.rmap`, луа-скрипты и паки лежат вместе.
Сервер сам находит единственную `*.rmap`, стримит все `*.pak` и грузит скрипты рядом с картой —
никакого ручного выбора карты/паков.

Из корня репозитория:

    gradle :dedicated-server:installDist
    ./dedicated-server/build/install/dedicated-server/bin/dedicated-server \
        --data-dir examples --port 27800 [--tick-rate 20]

`--tick-rate` (по умолчанию 20, допустимо 1..240) задаёт частоту мировых тиков — от неё зависят
`entity.on_tick`/`engine.on_tick` (патруль крысы, тосты `sky.lua`) и любые таймеры скриптов.

Содержимое host-папки:

    gradle :pak:installDist
    java -cp "pak/build/install/pak/lib/*" rpg.engine.pak.PakTool pack \
        --root assets-src --out assets/basic.pak \
        --resize sprite=32x64 --resize tile=32x16
    cp assets/basic.pak examples/host/

Клиент (карта рендерится **локально**, тот же файл из host-папки):

    gradle :desktop-client:installDist
    ./desktop-client/build/install/desktop-client/bin/desktop-client

или через настройки в игре: `Menu → Settings` указывает адрес сервера (`localhost`), `data/host`
подхватывается автоматически.

При подключении сервер стримит паки клиенту: видны спрайты сущностей по ИМЕНАМ (префаб сущности
в `.rmap` = имя `sprite/*` в паке: `arch`, `chest`, `guard`, `rat`…; игрок всегда `player`) и
текстурированные тайлы `tile/0..11`, экран **LOADING** с прогрессом скачивания; паки кэшируются
в `~/.openrpgator/data/pakcache` и повторно не скачиваются. Размер сущности задаётся параметром
`scale`: в `.rmap` (поле Scale в редакторе) или в Lua через `entity.set_scale(n)`.

Управление: **WASD/стрелки** — движение (относительно камеры), **L** — взаимодействие,
**J/K** — primary/secondary, **Esc** — назад. Подходить к NPC нужно ближе ~2 тайла.

## HUD и здоровье — как это устроено (host-driven, без хардкода в движке)

Движок/клиент **ничего не знают про HP**. Механика целиком скриптовая:

1. `hud.lua` держит здоровье игроков в локальной Lua-таблице (`hps[id]`, старт 100).
2. Список подключённых игроков скрипту сообщает хост-сервер (`world.players()`), а не движок.
3. Зоны рун проверяются дистанцией от `world.find("lava")`/`world.find("heal")` каждую итерацию
   `engine.on_tick`: ±1 HP/тик с капом 0..100.
4. HUD — это **host-инициированная схема**: скрипт собирает Lua-таблицу виджетов
   (`panel` + `bar` + `text`) и строки, и шлёт через `engine.layout(player, widgets, strings)`.
   Клиент — «тупой рендерер»: рисует по схеме (полоска по `value/max`, текст по индексу строки),
   не зная, что это про здоровье.

Схема виджетов протокола (UiLayout kind `"layout"`, координаты и размеры — доли экрана 0..1,
цвета — RGB(A) 0..1, `ref` — индекс в `strings`):

    {"type":"panel","x":..,"y":..,"w":..,"h":..,"bg":[r,g,b,a]}
    {"type":"bar",  "x":..,"y":..,"w":..,"h":..,"value":n,"max":m,"fill":[r,g,b],"back":[r,g,b]}
    {"type":"text", "x":..,"y":..,"ref":idx,"size":dp,"color":[r,g,b]}

Так хост может построить из примитивов любой HUD (мана, квесты, босс-бар) — клиенту не нужны
изменения.

## Что проверить вручную

1. Спавн → сразу срабатывает арка входа: диалог → телепорт на площадь.
2. **L** у Стражника → ветка диалога, переоткрытие меняет реплику (вложенный диалог).
3. Старейшина: взять поручение, отойти, снова **L** → ветка «как продвигается».
4. Торговец: купить меч; повторно — «не продаю».
5. Сундук: **L** → тост + сущность исчезает из снимка.
6. Крыса: постоять рядом ~1 сек — она блуждает; **L** — «ПИ!».
7. Каждые 6 секунд — тост от `sky.lua` («облака … Тик #N»).
8. Арка выхода (16,4) — возврат к спавну.
9. Размеры сущностей: крыса заметно мельче (0.75 из `rat.lua`), арка (1.35) и колодец (1.25) крупнее — `scale` из карты; сущности-персонажи 1.0.
10. **HP-бар**: слева сверху панель «Здоровье», полоска и число `HP 100/100`; значение меняется на рунах. Контрольные точки:
    - встать на пылающую руну (15,11) → HP падает на 1/тик, полоска убывает, число уменьшается;
    - встать на светлую (6,12) → HP растёт до 100 (кап);
    - клиент не знает про «здоровье» — это схема от `hud.lua` (проверка: у полоски нет движкового понятия HP).
11. Целитель (6,4): **L** → диалог с ветками про руны и здоровье; повторные ветки меняют реплику.
12. Угрозы проверяются теми же кнопками: удержание движения плавно ведёт персонажа (повторная отправка), движение — от камеры, а не от «севера/юга» карты.

## Oткрытый фронт работ (по итогам хоста)

Уже работает: engine Lua API v0.4 (диалоги/тосты/триггеры/телепорты), сетевой пулл `UiLayout`
(старые `Notify/Dialog/DialogResponse` для совместимости), десктоп- и Android-клиент рендерят
тайлы+спрайты+диалоги+тосты. Осталось для полноценной игры:

- **Карта по сети.** Сейчас клиент читает `.rmap` с диска (host-папка `data/host`). Нет пакета карты от сервера — подменяя файл, два клиента увидят разное. Нужен `Map`-пакет или уже `pak`-стрим.
- **Тайловые коллизии.** Слой `collision` в `.rmap` пока не влияет на движение: `CollisionWorld` учитывает только сущности. Стены проходимы.
- **Анимации/атласы.** Спрайты `.pak` (однокадровые) стримятся и рендерятся; нет атласов, анимаций ходьбы и транзитивных смен спрайта по состоянию.
- **Инвентарь/мобы/бой.** Покупка меча и сундук — только тосты; нет компонента-инвентаря.
  Здоровье — уже host-механика: HP хранится и применяется в Lua (`hud.lua`), клиент лишь рисует
  схему `engine.layout`; движок про HP не знает. Нет урона от мобов, смерти и воскрешения —
  их тоже можно написать скриптами на том же принципе.
- **Персистентность и мультиплеер-квесты.** Состояние квеста живёт в скрипте («первый игрок взял квест»); нет сохранений мира, и разные игроки делят одно состояние без учёта игрока.
- **AI-патруль** — примитивный (телепорт точки через `set_position`, мимо `CollisionWorld`); нет pathfinding/обхода стен.
- **Android-клиент** собирается в APK: гостевая вью (snapshot, тайлы/спрайты из атласа, тосты/диалоги
  по `UiLayout`, host-HUD по схеме), embedded-сервер из `data/host`, удержание кнопок движения с
  повторной отправкой (50 мс), движение от камеры и сворачиваемая верхняя панель — но ждёт проверки
  на устройстве (SDK-сборка CI).
